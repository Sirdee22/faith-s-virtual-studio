# Faith's Virtual Studio

Build a premium, modern, interactive, fully responsive personal portfolio website for a freelance Virtual Assistant named Faith.

The website will be used as Faith's professional portfolio and will be shared with potential clients from multiple freelancing platforms such as Fiverr, Upwork, Freelancer.com, and other freelance marketplaces.

The website must have two connected parts:

A beautiful public-facing portfolio website that potential clients can browse.

A simple private admin dashboard where Faith can log in with a password and manage the content displayed on the public website.

The admin system must be extremely simple. Faith should NOT need to understand databases, code, SQL, Supabase, or technical backend management in order to update her website.

==================================================
BRAND AND VISUAL DIRECTION

The visual style should be modern, elegant, minimal, premium, and interactive.

PRIMARY COLOR PALETTE:

White: #FFFFFF

Warm cream: #F8F5EF

Black: #171717

Dark charcoal: #333333

Light gray for subtle borders: #EAEAEA

White should be the dominant background color.

Use cream as a secondary background for selected sections to create visual separation.

Use black primarily for:

Headings

Navigation

Buttons

Important text

Icons

Borders where appropriate

Avoid excessive use of cream or dark backgrounds. The website should feel bright, spacious, clean, and premium.

TYPOGRAPHY:

Use a modern, elegant sans-serif typeface with a strong typography hierarchy.

Headings should be large and confident.

Body text should be highly readable.

Use generous spacing and whitespace.

Avoid overly decorative fonts.

==================================================

ADMIN LOGIN

Create a private login page at:

/admin

The administrator must log in using a password.

There should NOT be public administrator registration.

The administrator should be able to set the initial password during the website setup/deployment process.

Important security requirements:

Do NOT hardcode the password into frontend JavaScript.

Do NOT store the password in plain text.

Do NOT rely on a frontend-only password check.

Do NOT expose authentication credentials to visitors.

Authenticate securely on the server/backend.

Maintain a secure authenticated session.

Include a logout function.

Protect all admin routes.

Protect all create/update/delete operations.

Prevent unauthorized users from modifying website content.

If Supabase is used internally, use it only as the underlying infrastructure.

The website owner should never need to open the Supabase dashboard to manage normal website content.
